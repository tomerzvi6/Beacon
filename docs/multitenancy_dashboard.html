תהליך הרשמה של משפחה חדשה

1

המטפל הראשי פותח אפליקציה בפעם הראשונה

רונית לוחצת "כניסה עם Apple" — Apple מחזירה JWT token ייחודי

apple_user_id = "001.abc123xyz"
2

Supabase יוצר 3 רשומות בבת אחת

משפחה, משתמש, וקישור ביניהם — בתוך Transaction אחד

INSERT INTO families → { id: 'AAA', patient_name: 'אבא כהן' }
INSERT INTO users → { id: 'U1', name: 'רונית', apple_id: '001.abc...' }
INSERT INTO members → { user_id: 'U1', family_id: 'AAA', role: 'admin' }
3

רונית שולחת לינק הזמנה לדניאל

לינק מכיל token מוצפן שמקשר אוטומטית לאותה משפחה (family_id: AAA)

https://beacon.app/join?token=ENCRYPTED_AAA_TOKEN
4

דניאל לוחץ לינק → Apple Sign-In → נכנס לאותה משפחה

token מפוענח → דניאל מתווסף למשפחה כהן עם role: member

INSERT INTO members → { user_id: 'U2', family_id: 'AAA', role: 'member' }
5

מכאן הכל אוטומטי

כל request שדניאל שולח מכיל את ה-JWT שלו → Supabase יודע שהוא family AAA → RLS מסנן הכל

3

ה-DB בפועל — לחץ על משתמש כדי לראות מה הוא רואה

-- השאילתה שנשלחת מהאפליקציה:
SELECT * FROM tasks
-- RLS מוסיף אוטומטי:
WHERE family_id = 'AAA'
✅ 2 שורות מוחזרות
family_id משימה סטטוס שובץ ל
AAA לקנות תרופות מהרוקח פתוח רונית
AAA תיאום עם האונקולוג הושלם דניאל
BBB ביקור פיזיותרפיה פתוח שרה
BBB תרופות ערב — זופרן פתוח —
4

איך הבידוד עובד — Row Level Security

הקוד שמגדירים פעם אחת בסופאבייס

-- מגדירים על כל טבלה (tasks, medications, documents...)
CREATE POLICY "family_isolation" ON tasks
  USING (family_id = get_my_family_id());

-- פועל אוטומטי על כל SELECT / INSERT / UPDATE / DELETE
-- אין צורך לשנות שום קוד באפליקציה — DB עושה הכל
🔒
נאכף ברמת PostgreSQL — לא ברמת האפליקציה. גם אם יש bug בקוד, מידע לא "דולף".
⚡
אוטומטי לחלוטין — כל טבלה שתוסיף בעתיד תקבל אותה policy. פעם אחת, לנצח.
🚫
לא ניתן לעקוף — גם אם משתמש ישנה ידנית את ה-family_id ב-request, הDB מתעלם.
📋
Audit log אוטומטי — Supabase מתעד כל ניסיון גישה. חיוני לרגולציה רפואית.
